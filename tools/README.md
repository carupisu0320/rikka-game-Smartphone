# 演出の測定データの自動更新

`js/16-fx-sync.js`（演出の「盛り上がる瞬間」＝音ハメ用の測定データ）を、自動で作り直すツールです。

## ふだんの流れ

演出の絵（`js/02-effects.js` の `FXS.xxx` など）を変えたら：

1. `node tools/measure-fx.js` を実行します。絵を変えた演出と、新しい演出だけを、測り直します。
2. `node --test "tests/*.test.js"` でテストを通します。
3. その演出を実際に流して、音の合い方を耳で確かめます。ずれていれば、`js/15-fx-sounds.js` の音を調整します。

絵を変えたのに測り直さないと、CI（`tests/fxsync.test.js`）が落ちて、どの演出が古いかを教えてくれます。

## 最初に1回だけ

```
npm i -D playwright
npx playwright install chromium
node tools/measure-fx.js --baseline
```

`--baseline` は、いまの測定データを「最新」とみなして、絵のハッシュだけを記録します（測定データは変わりません）。

## コマンド

| コマンド | 何をするか |
|---|---|
| `node tools/measure-fx.js` | 古くなった演出だけを測り直す |
| `--check` | 古い演出を一覧にするだけ（ブラウザ不要。終了コードで成否が分かる） |
| `--baseline` | ハッシュだけを記録する |
| `--only riichi:thunder,win:book` | 指定した演出だけを測り直す |
| `--all` | すべて測り直す。**過去の値は約6割しか一致しません**（手で調整した値も消えます） |
| `--gif` | 開発者マッチのGIF（`img/dev-match.gif`）の測定データも更新する（`--gif-file パス` で別のGIFも可） |
| `--dry` / `--out ファイル` | 書き込まない／別のファイルに書く |

## 仕組み

- 本物のゲーム（`index.html`）をヘッドレスのChromiumで開き、**時間を止めた状態**で演出を1コマずつ描きます（60コマ/秒、画面 360×640、乱数の種は固定）。毎回同じ絵になるので、結果が安定します。
- 測るのは、演出の絵（キャンバス）だけです。黒の上に重ねたときの「明るさ」と、コマ同士の「動き」を測り、`env`（明るさの変化）と `on`（盛り上がる瞬間）を作ります。
- 「古い」かどうかは、演出ごとの描画関数と、共通の部品（`_fR`・`fxGlow`・`fxStartScene` など）のハッシュ、演出の長さで決めます。共通の部品を変えると、すべてが対象になります。

## 気をつけること

- 盛り上がる瞬間の検出は、元の測り方が分からないため、既存の測定データと**約6割**一致します（時刻のずれは平均0.02秒）。雷のように光る時刻が決まっている演出は、ほぼぴったり合います。花びら・雨など、ランダムな演出は、数や位置が変わることがあります。
- 共通の部品の一覧は `tools/lib/fxsync-file.js` の `COMMON_NAMES` です。新しい共通の部品を `02-effects.js` に足したら、ここにも足してください。
- 標準の演出（`win:rainbow`・`win:default`・`ron:default`）は、測定データなしで鳴らす決まりなので、対象外です。
